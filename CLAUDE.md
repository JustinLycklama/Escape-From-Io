# Escape From Io

Indirect-control RTS in Unity. **Target is PC only (Windows, mouse + keyboard).** The game was originally mobile-first.
Ignore the touch/joystick/mobile code: don't extend it, don't design around it, and don't spend effort on Android/iOS. The player queues tasks (mine, build, haul) and robots with limited battery pull work from per-type queues.
The goal is to build an escape shuttle before you run out of robots. The repo folder is named "Pathfinding" for historical reasons.

**Read `ARCHITECTURE.md` before non-trivial changes.** It covers systems, coordinate spaces, the task pipeline and known issues.

## Environment

- Unity **2019.2.9f1** (`ProjectSettings/ProjectVersion.txt`). Don't upgrade casually. An upgrade is a deliberate, separate task on its own branch.
- C# / .NET 4.x scripting runtime. `*.csproj`/`*.sln` are generated by Unity and gitignored, so never edit them.
- Windows dev machine, PowerShell. The Unity editor must be used to run/play. There is no CLI build or test runner set up yet.
- Real scenes: `Assets/Scenes/TitleScene.unity` (index 0) and `Assets/Scenes/GameScene.unity` (index 1). Others are sandboxes or vendor demos.

## What's ours vs vendor

First-party code lives only in: `Assets/Game Management/`, `Assets/Game Objects/` (`Units/`, `Buildings/`, the top-level `.cs` files,
`Voxel Ships/RandomShipGenerator.cs`, `Voxel Ships/StationShip.cs`, `L3D_Assets/EarthElementalController.cs`), `Assets/Map Generation/`,
`Assets/PathFinding/`, `Assets/Math/` and `Assets/UI/` (except `PieChart/`, `SciFi UI Pings VFX/`, `Assets/Icons/`).
Everything else in `Assets/` is asset-store/vendor content: **don't modify it, and exclude it from searches and reviews.**

## Conventions in this codebase

- **Find managers with `Script.Get<T>()`** (Constants.cs), not `FindObjectOfType`. A new manager needs a `Script` entry, an `allScripts` entry and a Unity tag,
  otherwise `Get` silently returns null.
- **Observer pattern**: subscribers call `RegisterFor…(this)` and implement a `…Delegate` interface. Every Register needs a matching `End…` in `OnDestroy`.
- **Blueprints**: new units and buildings are `static Blueprint` fields on `Unit.Blueprint` / `Building.Blueprint`, with cost, a `Resources/` prefab path,
  an icon name and an optional placement predicate. The prefab must exist at that path.
- **Work happens through tasks**: gameplay actions create `MasterGameTask`s (made of `GameTask` steps) and `TaskQueueManager.QueueTask` them.
  Never drive a unit directly.
- **Respect pause**: coroutines check `playerBehaviour.gamePaused` and timers go through `TimeManager.AddNewTimer`.
- **Coordinates**: be explicit about which space a value is in (`LayoutCoordinate` / `MapCoordinate` / `PathGridCoordinate` / `WorldPosition`) and use the
  conversion helpers in `MapStructs.cs` / `MapsManager`.
- **Tutorial hooks**: gameplay code calls `TutorialManager.sharedInstance.Fire(TutorialTrigger.X)`. Keep these when refactoring.
- Style: K&R braces on the same line, `camelCase` fields, `PascalCase` methods, interfaces named `…Delegate` without an `I` prefix. Match the surrounding code.

## Gotchas

- Static state persists across scene loads (task counter, `UnitManager.unitCount`, singletons). Reset it explicitly if you add more.
- `Resources.Load` paths and Unity tags are stringly-typed. Renaming a prefab or tag breaks things at runtime, not at compile time.
- Task assignment can stall. A watchdog in `Narrator.CheckForTaskQueueManager` restarts it. See ARCHITECTURE.md → Known issues before touching `TaskQueueManager`.
- Firebase/Parse DLLs and several vendor `.obj` models were never committed. A fresh checkout needs the Firebase Unity SDK 6.14.1 re-imported.
  `docs/` is the GitHub Pages site, not developer docs.
